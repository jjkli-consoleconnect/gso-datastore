JIRA DATAPipe VPC Connection Guide
===================================
Date: 2026-08-10

WHY VPC IS NEEDED
-----------------
Jira (consoleconnect.atlassian.net) is behind the company VPN/firewall.
A Cloud Function with default internet egress CANNOT reach Jira.
You MUST attach a VPC Connector and set egress to ALL to route traffic
through the private network where Jira is reachable.


VPC CONNECTORS
--------------
PROD:
  Project:  pccw-internal-virtual-agent
  Region:   europe-west2
  Connector: eu-prod-wanda-vpc-conn

UAT:
  Project:  pccw-internal-virt-agent-uat
  Region:   europe-west2
  Connector: eu-uat-wanda-vpc-conn


STEP 1: CHECK IF VPC CONNECTOR EXISTS
-------------------------------------
PROD:
  gcloud compute networks vpc-access connectors list \
    --region=europe-west2 \
    --project=pccw-internal-virtual-agent

UAT:
  gcloud compute networks vpc-access connectors list \
    --region=europe-west2 \
    --project=pccw-internal-virt-agent-uat

If the connector is missing, create it:

  gcloud compute networks vpc-access connectors create eu-prod-wanda-vpc-conn \
    --network=default \
    --region=europe-west2 \
    --project=pccw-internal-virtual-agent \
    --range=10.8.0.0/28


STEP 2: CREATE SERVICE ACCOUNT
------------------------------
  gcloud iam service-accounts create jira-sync-runtime \
    --project=pccw-internal-virtual-agent

Grant these roles:
  - roles/secretmanager.secretAccessor  (read Jira credentials)
  - roles/bigquery.jobUser                (run BQ queries)
  - roles/bigquery.dataEditor             (write to BQ tables)


STEP 3: STORE JIRA CREDENTIALS IN SECRET MANAGER
------------------------------------------------
  echo -n "your-jira-email@consoleconnect.com" | \
    gcloud secrets create jira-user-email --data-file=- \
    --project=pccw-internal-virtual-agent

  echo -n "your-jira-api-token" | \
    gcloud secrets create jira-api-token --data-file=- \
    --project=pccw-internal-virtual-agent


STEP 4: DEPLOY CLOUD FUNCTION WITH VPC
--------------------------------------
The two critical flags are:
  --vpc-connector  (attach to VPC)
  --egress-settings=all  (route ALL traffic through VPC)

PROD example:
  gcloud functions deploy jira-tickets-sync \
    --gen2 \
    --runtime=python311 \
    --region=europe-west2 \
    --source=. \
    --entry-point=main \
    --trigger-http \
    --no-allow-unauthenticated \
    --memory=1024MB \
    --timeout=540s \
    --vpc-connector="projects/pccw-internal-virtual-agent/locations/europe-west2/connectors/eu-prod-wanda-vpc-conn" \
    --egress-settings=all \
    --service-account=jira-sync-runtime@pccw-internal-virtual-agent.iam.gserviceaccount.com \
    --project=pccw-internal-virtual-agent

UAT example (jira-to-helix style):
  gcloud functions deploy mss-to-remedy-create-uat \
    --gen2 \
    --runtime=python312 \
    --region=europe-west2 \
    --source=. \
    --entry-point=main \
    --trigger-http \
    --no-allow-unauthenticated \
    --memory=512MB \
    --timeout=120s \
    --vpc-connector="projects/pccw-internal-virt-agent-uat/locations/europe-west2/connectors/eu-uat-wanda-vpc-conn" \
    --egress-settings=all \
    --service-account=jira-sync-runtime@pccw-internal-virt-agent-uat.iam.gserviceaccount.com \
    --project=pccw-internal-virt-agent-uat


STEP 5: SET UP SCHEDULER (for periodic triggers)
------------------------------------------------
  gcloud scheduler jobs create http jira-tickets-sync-scheduler \
    --schedule="*/15 * * * *" \
    --uri="https://REGION-PROJECT.cloudfunctions.net/jira-tickets-sync" \
    --http-method=POST \
    --oidc-service-account-email=jira-scheduler-invoker@pccw-internal-virtual-agent.iam.gserviceaccount.com \
    --location=europe-west2 \
    --project=pccw-internal-virtual-agent


STEP 6: VERIFY
--------------
1. Check function deployed with VPC:
   gcloud functions describe jira-tickets-sync \
     --region=europe-west2 \
     --project=pccw-internal-virtual-agent \
     --format="value(serviceConfig.serviceAccountEmail,serviceConfig.vpcConnector)"

2. Test Jira API call from function logs — should NOT get connection timeout.

3. Check BigQuery table has new rows after function runs.


KEY REMINDERS
-------------
- ALWAYS use --no-allow-unauthenticated for prod Jira functions
- ALWAYS use --egress-settings=all (not "internal-and-cloud-apis")
- ALWAYS use the dedicated service account, NOT the default compute SA
- Pin requests==2.33.0 in requirements.txt
- Prod sync functions write BQ to UAT project (pccw-internal-virt-agent-uat)
- Read Jira secrets from PROD project Secret Manager
